两个 Person 类，让我两小时没编译出来

2026 年 11 月 22 日 · 排错

代码昨天还能跑，今天一按运行，整个项目红了。VS Code 给的提示是这三行：

The method keepPet(Cat, String) is undefined for the type Person
The type Person is already defined
The constructor Person(String, int) is undefined

第一反应当然是「我哪里写错了」。把 Polymorphism.java 从头到尾看了一遍，keepPet 明明白白写在 Person 里，参数类型也对得上。改了半天，报错一个字都没变。

真凶是中间那句

The type Person is already defined——这个 Person 已经被定义过了。可我这个文件里只有一个 Person。

问题出在另一个文件：练继承的时候，我在 ExtendsDemo3.java 里也写了一个 Person。而这两个文件的第一行都没有 package，于是它们全被算进了同一个「默认包」。

Java 的规矩是：一个包里不能有两个同名类。编译器不知道我说的 Person 是哪一个，索性把相关的一切都判成不存在——所以 keepPet 和构造器跟着一起报错，看起来像我写错了。

包（package）不是靠文件夹分的，是靠文件第一行的 package 语句。子文件夹里的文件不写 package，就全在默认包里。

怎么确认的

不看 VS Code，直接用 javac 试：

  • 只编译 HARD TEST 这一个文件夹 → 通过，0 个错误
  • 把整个 java.test 一起编译 → duplicate class: Person、duplicate class: Student

到这里就确定了：代码没问题，是我把十几个练习塞进了同一个工程。

怎么解决

  1. 把这个练习的文件夹单独挪出去，作为独立文件夹打开。两个 Person 立刻分属两个工程，互不相干。
  2. 清一次 Java 语言服务器缓存（Java: Clean Java Language Server Workspace）。因为之前还残留了 fu.class 和 Fu.class 这种只差大小写的产物，构建时会直接抛异常中断。

如果非要把所有练习放一个工程，那就得老老实实按包组织：目录名必须是合法包名（小写、无空格、无中文），每个文件第一行写 package hard; 之类。HARD TEST 这种带空格的名字，永远当不了包名。

教训

  1. 看到「方法不存在」，先往上翻，看有没有「已经定义」——后者才是原因。
  2. 一个练习一个文件夹。省下的不是磁盘空间，是排错时间。
  3. 编译器报的错经常不是根因，只是根因的影子。
